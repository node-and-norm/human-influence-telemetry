# Controlled evidence-update representation benchmark

## Question and scope

The identifier HIT-EU-001 uses EU for evidence update. It does not refer to the European Union or imply regulatory-sandbox participation.

Can two equivalent-content representations support correct identification of explicitly injected evidence changes, while retaining stated limits? This first run is an AI-assisted rehearsal, not a human study, a validation of HIT's six dimensions, or a comparison of complete workflows. The HIT-inspired graph separates propositions and typed evidence/qualification relations. The capable structured-review table places the same propositions and links in rows. Both use the same source dossier, qualifications, updates and response contract. The navigation labels differ; the available semantic relationships do not.

Agency A, Board B, Cohort A, all dates in 2040 and every supplied source are constructed teaching material. Their structure was inspired by issues in the Ofqual development example. They add no historical evidence or new accepted scores to that case. These are not full HIT assessments. Judgment and other dimensions outside the constructed task receive no finding.

## Design fixed before trial

Five separate, noncumulative scenarios start from one eight-proposition packet: an unchanged control, withdrawal of the advice-panel source, correction of the direction's event date, an equally admissible contrary implementation account, and receipts for five named candidates. The control detects unprompted changes. Updates never accumulate. Reuse of one packet does not create statistically independent observations. The separate oracle fixes only consequences deliberately built into these scenarios. It does not settle a contested historical interpretation.

The two passes use separate newly tasked AI assistants with the same underlying model class. Each receives common instructions, the shared dossier, updates and one representation. Neither is intentionally given the oracle or the other response. They may retain broader system context, and technical access isolation is not guaranteed. These are separate passes, not independent evaluators, randomized participants or blinded human trials. Record the actual model identity if available and access limitations in the report; do not infer independence from separate agent labels. No new Jev call is planned.

Before either pass, commit and push this protocol, both packets, dossier, updates, instructions, oracle, design manifest, runner and unit tests. Read and critique these materials first. Freeze their exact bytes through the Git commit. Only then create actual response files under responses/. Each response must name that commit and the digests of its permitted input files. Never derive observed responses from the oracle. Unit-test fixtures are synthetic software tests and must stay separate from trial files.

Retain each executor's first response, including a structurally invalid or incomplete response. This run allows no substantive repair, replacement response or retry. The coordinator may document an execution failure and why the scorer could not assess it; a later successful attempt must not replace the first observation. Any revised task or new attempt belongs to a separately identified run with its own provenance.

## Outcomes and error accounting

For each method, report affected-proposition true positives, misses and false positives over 40 proposition opportunities. Four are deliberately affected; 36 are unchanged. Report exact documentary-state agreement separately over 40 rows, and qualification-enum agreement separately over 35 rows. Preserve scenario-level and item-level differences. The date correction requires substantive revision even though its documentary status stays supported. Withdrawal makes the panel proposition unsupported, not disproved. The conflict changes occurrence support without erasing the fact of reporting. New receipts change only the recipient evidence they cover.

Enum agreement checks explicit scope choices, including unresolved material access, regulatory direction versus software operation, five-recipient delivery versus universal delivery, and unresolved consequential harm. It does not establish that the accompanying prose faithfully preserves those limits. The scorer also checks whether the date update names the corrected date and whether the receipt update names all five recipients; these exact tokens are narrow content checks, not semantic validation. Human review of statements and rationales remains pending. Report this separately from automated agreement. Do not produce a combined accuracy percentage, inferential statistics, a time-saving claim or a utility ranking.

Retain errors, ties and unexpected changes. An error can reveal a defect in instructions, representation or assistant execution; this two-pass design cannot identify its cause. A perfect run would show only that these assistants answered this small constructed task consistently with its design. It would not show that HIT is needed, reliable in institutions, superior to structured review, independently validated, or ready for v1.0.

## Analysis and revision rules

The runner checks semantic input equivalence, hashes, frozen Git bytes, complete response structure and references before scoring. It never generates a response. Invalid structure fails separately from a substantive mismatch; valid wrong enums remain observable errors. Reanalyse the saved responses without contacting a model. If a post-freeze ambiguity affects interpretation, preserve the original run, document it, and use a new versioned protocol for any changed task or oracle.

This development artifact can inform a later author-supervised pilot. It satisfies no independent human-review, current-contract external-rater replication, regulatory-sandbox or release gate. All results remain pending author review.
